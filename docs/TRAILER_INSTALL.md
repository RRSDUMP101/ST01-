### 2.2 แกนของแบบ → แกนของโปรแกรม

แบบหางวาดด้วย **+Y = ท้ายหาง** (ไฟท้าย ป้ายทะเบียน ประตูท้าย) **−Y = หัวลาก**, Z ขึ้น
โปรแกรมใช้ X ไปท้ายรถ, Z ขึ้น, +Y = ขวาของรถ → ตอนนำเข้าหมุน 90° รอบแกน Z: **X(โปรแกรม) = Y(แบบ), Y(โปรแกรม) = −X(แบบ)**
(หมุนจริง ไม่สะท้อน – ชิ้น `_Mirror` ยังอยู่ด้านเดิม) · จุดศูนย์ของงานหาง = **ศูนย์หัวบอลพ่วง** เมื่อมีชิ้นหัวลาก (ข้อ 3.3)

ขั้น 12 ไม่ใช่ขั้นใหม่: คือขั้น `tow_hitch`, `tow_wiring`, `tow_ball`, `tow_brake` ใน `core/install_manual.py` ที่ตรวจตาม BEMM 1.14 อยู่แล้ว –
ในภาพ 3 มิติแสดงรถเป็นชิ้นอ้างอิง (กลุ่ม "รถ (อ้างอิง)") กับหางที่ประกอบเสร็จ

## 5. ออกแบบโปรแกรม

### 5.1 การไหลของงาน

```
ไฟล์ ZW3D ของหาง (.Z3)  ──►  ชื่อ · ชุดประกอบ · ตำแหน่ง · กล่อง  ──┐
                                                                 ├─►  โมเดลหาง (.rrsasm)  ──►  ลำดับ 12 ขั้น  ──►  แท็บ ประกอบ 3D + คู่มือ PDF
ไฟล์ STEP ที่ส่งออกจาก ZW3D    ──►  รูปทรงจริงของแต่ละชิ้น  ───────┘      จับคู่ชิ้นด้วยตำแหน่ง              (ตั้งได้ใน ✎ แก้ไขขั้นตอน)
```

* **ยังไม่มี STEP** → เปิดจาก `.Z3` อย่างเดียวได้เลย: ชิ้นวาดเป็นกล่องตามตำแหน่งจริง ใช้จัดขั้น/ตั้งชื่อ/ทิศแยกชิ้นได้ก่อน
  (กล่องของบางชิ้นใหญ่เกินจริง – แจ้งในหน้าจอ) · ได้ STEP แล้วกด **รับรูปทรงจากไฟล์อื่น** – ชิ้นที่ตำแหน่งตรงกันรับรูปทรงไป ขั้น/ชื่อที่จัดไว้ไม่หาย
* แบบนี้ใช้กับกระบะได้ด้วย (ข้อ 7.5 ของเอกสาร Ford: จับคู่ชื่อจาก `.Z3` กับ IGES ได้แค่ 44 จาก 305 ชิ้น – เพราะเป็นคนละรุ่น)

### 5.2 สิ่งที่ต้องทำในโค้ด

| งาน | ไฟล์ | รายละเอียด |
|---|---|---|
| ลำดับประกอบตามชนิดสินค้า | `core/assembly3d.py` | แยก `TRAY_PHASES / TRAY_NAMED / TRAY_RULES / TRAY_SPELLING / FASTENER_GROUPS` ออกเป็น **โปรไฟล์ลำดับ** (`SequenceProfile`) – มีโปรไฟล์ "กระบะพื้นเรียบ" (ของเดิม ทำงานเท่าเดิม) และ "หางลากพื้นเรียบตู้ทึบ" (ข้อ 4) · `apply_tray_sequence` → `apply_sequence(model, profile)` · `tray_sequence_fits` เลือกโปรไฟล์ที่ชื่อชิ้นเข้ากันมากที่สุด |
| เปิด `.Z3` เป็นโมเดลประกอบ | `core/cad_import.py`, `core/z3_reader.py` | `placed_instances` → ชิ้นกล่องตามตำแหน่ง + ชื่อ + ชุดประกอบเป็นกลุ่มย่อย · หมุนแกนข้อ 2.2 · ชิ้น `_Mirror` ได้ชื่อด้าน ซ้าย/ขวา (`tidy_names`) |

| ชื่อญี่ปุ่น / ชื่อไฟล์เพี้ยน | `core/z3_reader.py` | ถอดชื่อที่มีอักษรเสียเป็น cp932 ถ้าได้ข้อความสมบูรณ์ (ทดลองกับไฟล์นี้แล้วได้ครบ) · `Z3Library.locate` เทียบชื่อโดยข้ามอักษรที่ถอดไม่ได้ |
| สินค้าหางลากพื้นเรียบตู้ทึบ | `core/install_manual.py` | เพิ่มสินค้า "หางลากพื้นเรียบตู้ทึบ 1.8 × 5.7 ม." (ขนาดจากแบบ) คู่กับ "หางลากถาด 5.0 × 1.8 ม." (`trailer_5m`) เดิม · ความกว้างรวมจากโมเดลแทนค่าคงที่ `TRAILER_OUTER_WIDTH` |
| หน้าจอ | `ui/pages/assembly3d.py` | ข้อความ "หางลากยังไม่มีโมเดลตัวอย่าง" → ปุ่ม **เปิดโมเดลหาง (.Z3 / .rrsasm)** · ตัวเลือกโปรไฟล์ลำดับ เมื่อเดาไม่ได้ |
| เทสต์ | `tests/test_assembly3d.py`, `tests/test_z3_reader.py` | โปรไฟล์กระบะยังได้ 13 ขั้นเดิม · โปรไฟล์หางได้ 12 ขั้นจากโมเดลตัวอย่างที่สร้างในเทสต์ (ไม่ใช้ไฟล์ของลูกค้า) · หมุนแกน · หาไฟล์ชื่อเพี้ยน |

### 5.3 ลำดับการทำ (เสนอ)

1. **ตัวอ่าน**: หาไฟล์ชื่อเพี้ยน + ชื่อญี่ปุ่น → ใบรายการหางครบ 431 ชิ้น (ไม่ต้องรอ RRS)
2. **เปิด `.Z3` เป็นโมเดลกล่อง** + หมุนแกน → เห็นหางทั้งคันในแท็บ ประกอบ 3D
3. **โปรไฟล์ลำดับ** + ลำดับหาง 12 ขั้น (ข้อ 4) → ทดลองบนโมเดลจริง ส่งภาพให้ RRS ดู
4. รับรูปทรงจาก STEP เมื่อได้ไฟล์ · ชิ้นข้อ 3.3 · ขั้นต่อพ่วงกับรถในภาพ 3 มิติ
5. คู่มือ PDF ของหาง + build Windows / macOS

## 6. ข้อที่ต้องให้ RRS ยืนยัน

1. ~~รุ่นของหาง~~ → **ยืนยันแล้ว (19 พ.ย.): หางลากพื้นเรียบตู้ทึบ** (ตู้ 1.8 × 5.7 × 2.3 ม. ประตูข้าง 4 บานต่อด้าน) – เป็นสินค้าใหม่ แยกจาก "หางลากถาด 5.0 × 1.8 ม."
2. ลำดับ 12 ขั้นในข้อ 4 ถูกต้องตามหน้างานไหม (เช่น ติดตั้งล้อก่อนหรือหลังขึ้นตู้)
3. ส่งออก **STEP (AP214) จากชุดประกอบบนสุด** ใน ZW3D ให้ด้วย – เพื่อรูปทรงจริง
4. ชิ้นข้อ 3.1: กล้อง RVC ติดที่หางหรือที่รถ · `Part004`, `Part005` คืออะไร อยู่ตรงไหน · ประตู/กันน้ำที่ยื่นออกคือท่าเปิดหรือไม่
5. `B-5070S` คืออะไร – ใช่กลอน/มือจับประตูไหม ติดบานไหน กี่ชุด · ส่งไฟล์แหวนรอง M8 ที่ขาด
6. ชื่อไทยของ `Part002 – Part006` · ชื่อไทยของบานพับที่เสนอในข้อ 3.2 ใช้ได้ไหม
7. รุ่นชุดลาก Ford ที่ใช้ (3.5T ลูกบอล Ø50 / 4.5T ลูกบอล Ø70) · น้ำหนักหางเปล่า · ความสูงพื้นตู้จากพื้นถนน · หางมีเบรกหรือไม่
