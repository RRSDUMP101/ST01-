# สิทธิ์การใช้งานและความปลอดภัย

ออกแบบจากการตรวจโค้ดทั้งโปรแกรม (5 ด้าน: บอทคีย์ Express, เอกสารสต็อก, คอมที่ใช้ร่วมกัน, มือถือ/ลิงก์ออนไลน์,
ความลับ/ไฟล์ข้อมูล) – พบ 71 ข้อ ตรวจซ้ำแบบหักล้างแล้วยืนยัน 53 ข้อ · ขนาดพอดีกับโรงงาน (คอม 1–2 เครื่อง, ~10 คน)

## 1. ผู้ใช้และบทบาท (เมนู ผู้ใช้ › ผู้ใช้และสิทธิ์)

* **ยังไม่มีผู้ใช้ = ใช้ได้ทุกอย่างแบบเดิม** (ไม่บันทึกชื่อ) · เพิ่ม **ผู้ดูแลคนแรก** = เปิดการเข้าสู่ระบบ
  → ได้ **รหัสกู้คืน** ครั้งเดียว (จดเก็บนอกคอม ใช้ตั้ง PIN ผู้ดูแลใหม่เมื่อลืม) · แนะนำผู้ดูแล 2 คน (นุ๊ก, โม)
* เข้าสู่ระบบ: เลือกชื่อ + PIN 4–8 หลัก · ผิด 5 ครั้ง ล็อก 1 นาที (เพิ่มเป็นเท่าตัวถึง 15 นาที) · **ดูอย่างเดียว** ไม่ต้องใช้ PIN
* ล็อกเองเมื่อไม่มีคนใช้ (ตั้งค่าเริ่มต้น 10 นาที) · ปุ่มชื่อผู้ใช้ที่แถบล่าง = สลับผู้ใช้ / ล็อก
* PIN เก็บเป็น hash (PBKDF2-SHA256 + salt) ใน `users.json` – ไม่เก็บ PIN จริง

| บทบาท | ใคร | ทำได้ | ทำไม่ได้ |
|---|---|---|---|
| ดูอย่างเดียว | ทุกคน / หน้างาน | ดูทุกหน้า พิมพ์ | บันทึกใด ๆ |
| ผลิต / เลเซอร์ | ช่าง, หัวหน้างาน | บันทึกผลผลิต, ทำใบร่าง | บันทึก/ยกเลิกเอกสารสต็อก |
| สโตร์ / คลัง | แอน | บันทึก PD OU RR FR, ยกเลิกใบที่ยังไม่เข้า Express, ยืนยันงานจากมือถือ, ส่งออกไฟล์ส่ง Express | **บันทึกใบปรับยอด (ตรวจนับ)**, คีย์/ใส่เลขที่ Express |
| วางแผนผลิต | แอม | Part List, แบบกระบะ, งานผลิต, เลเซอร์ | บันทึกเอกสารสต็อก |
| จัดซื้อ | ข้าวฟ้าง | Min/Max, ตารางรหัส, ใบรับ RR (ร่าง) | บันทึก/ยกเลิกเอกสาร |
| บัญชี / Express | แป้ง, เป้, เบนซ์ | คีย์เข้า Express, ใส่/นำเข้าเลขที่ Express, **บันทึกใบปรับยอด**, ยกเลิกใบที่เข้า Express แล้ว | แก้ลำดับการกดของบอท, ผู้ใช้ |
| ผู้ดูแล / IT | นุ๊ก, โม | ทุกอย่าง: ผู้ใช้, ตั้งค่าบอท, มือถือ, ลิงก์ออนไลน์ | แก้บันทึกการใช้งาน |

คนที่นับ (สโตร์) ไม่ได้เป็นคนบันทึกยอดที่ปรับเอง – ใบปรับยอดจากมือถือเก็บเป็นร่างให้บัญชีบันทึก
สิทธิ์ตรวจที่ตัวข้อมูล (`ui/state.py`, `core/access.py`) ไม่ใช่แค่ปิดปุ่ม – เมนู Ctrl+K หรือมือถือก็ผ่านการตรวจเดียวกัน

## 2. บันทึกการใช้งาน (audit log)

`audit/audit-YYYY-MM.jsonl` – ใคร ทำอะไร เมื่อไร กับเอกสารไหน ค่าเดิม → ค่าใหม่ เหตุผล: เข้าสู่ระบบ/ผิด PIN, บันทึก/ยกเลิก/ลบร่าง,
ใส่/เปลี่ยนเลขที่ Express (จากที่ไหน), คีย์ด้วยบอท (เริ่ม/จบ/หยุดกลางคัน/คีย์ซ้ำพร้อมเหตุผล), บทบาทมือถือ, ตั้งค่า
แต่ละบรรทัดมี hash ของบรรทัดก่อน – **ตรวจความครบถ้วน** บอกได้ว่ามีบรรทัดถูกแก้หรือลบ

## 3. เอกสารสต็อกและ Express

* บันทึก `library.json` แบบปลอดภัย (เขียนไฟล์ใหม่ก่อนแทนที่) + สำเนา `.bak` + สำเนารายวัน `backups/` 14 วัน
* ไฟล์เสีย → เก็บไว้ `library.corrupt-…` แล้วอ่านสำเนาล่าสุด แจ้งเตือน · ถ้าไม่มีสำเนาที่อ่านได้ **ไม่บันทึกทับ**
* เลขที่ Express ผ่านทางเดียว (ตรวจรูปแบบ/ชนิด/ซ้ำ, บันทึกผู้ใส่) · หน้า เบิก/รับ ไม่ทับเลขที่ที่ใส่จากที่อื่นอีก
* นำเข้าเลขที่จากไฟล์: แสดงก่อนใส่, ใส่เฉพาะใบที่บันทึกแล้วและยังไม่มีเลขที่
* ยกเลิกใบที่เข้า Express แล้ว: ต้องเป็นบัญชี/ผู้ดูแล + เหตุผล → ขึ้นรายการ **⚠ ต้องยกเลิกใน Express ด้วย**
* บอท: ถามยืนยันหน้าจอ **ก่อน** กดปุ่มใด ๆ, ไม่กดบันทึกแทนคน (ผู้ดูแลเปิดได้ – บันทึกไว้), ไม่พิมพ์ลง Excel/Word/เบราว์เซอร์,
  ตัดอักขระควบคุม, ปิดหน้าต่างระหว่างคีย์ไม่ได้, คีย์ซ้ำต้องใส่เหตุผล, "คีย์แล้ว" เมื่อคนกด **บันทึกใน Express แล้ว** เท่านั้น

## 4. มือถือ

* บทบาทเครื่องกำหนดที่คอมตอนสร้างรหัสจับคู่ – มือถือขอเป็น วางแผน เองไม่ได้ · รหัสที่ให้บทบาท/ใช้จากนอกโรงงานใช้ได้เครื่องเดียว
* ชื่อ "คอม"/"ระบบ" ใช้ไม่ได้ · ยืนยันงานจากมือถือบันทึกชื่อผู้ยืนยันบนคอม

## 5. ต้องทำโดยเจ้าของระบบ

* **ตั้ง repository GitHub เป็น private** (ตอนนี้เป็น public) – ไฟล์ตัวอย่างเปลี่ยนเป็นข้อมูลสมมุติแล้ว แต่ประวัติเก่ายังมี
* สำรองโฟลเดอร์ข้อมูลของโปรแกรมไว้นอกคอม (ไดรฟ์บริษัท) เป็นประจำ
* ขั้นต่อไป (P2): จำกัดเครื่องที่ใช้นอกโรงงานทีละเครื่อง, ใบรับรองมือถือจำกัดชื่อ, ส่งราคาทุนขึ้น Google Sheet เฉพาะเมื่อติ๊ก
