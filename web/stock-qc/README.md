# RRS Stock & QC (เว็บ)

ระบบสต็อก–จอง–จัดซื้อ–QC ตามแผน Phase 0–6 (`docs/PHASE0_STOCK_QC_AUDIT.md` และเอกสาร "RRS QC" ใน Google Drive)
หน้าเว็บไฟล์เดียว ใช้ได้ทั้งเป็น Artifact แบบส่วนตัวใน claude.ai และบน Cloudflare Worker (D1 + R2) ที่บันทึกข้อมูลแบบเดียวกับ RRS Sale Office

> สถานะ: **ระบบครบทุกเฟสสำหรับทดลอง (UAT)** ยังไม่เคย deploy ขึ้น Cloudflare จริง และยังไม่ได้ใช้กับข้อมูลจริง
> เซิร์ฟเวอร์ทดสอบใน Miniflare บนเครื่องเท่านั้น (ดู `worker/README.md`) ส่วน Google Drive และ Sales Office ทดสอบกับ server ปลอมในเครื่อง
> ผลทดสอบอัตโนมัติผ่านแล้วไม่ได้แปลว่าผ่านการตรวจรับของสโตร์/QC/บัญชี — ใช้หน้า "ทดสอบรับงาน (UAT)" บันทึกผลจริง

### หลักการที่ทำให้ยอดถูกต้อง

- ทุกคำสั่งตรวจครบก่อน แล้วได้ **commit เดียว** ที่มีทุกแถวที่เปลี่ยน — มีบรรทัดผิดบรรทัดเดียว ไม่มีอะไรเปลี่ยน
- commit เรียงลำดับ (seq) และต่อกันด้วย SHA-256 (`prev` → `hash`) แก้ย้อนหลังแล้วตรวจพบ
- คำขอทุกครั้งมี `requestId` ส่งซ้ำ (กดซ้ำ/เน็ตหลุด/เปิดโปรแกรมใหม่) มีผลครั้งเดียว
- บันทึกได้ทีละรายการ: ถ้ามีคนบันทึกก่อน คำสั่งถูกตรวจใหม่บนข้อมูลล่าสุด (สองคนเบิกชิ้นสุดท้าย สำเร็จคนเดียว)
- ยอด = ผลรวมประวัติเสมอ (`RRS.inventory.verifyBalances`), ยกเลิก = รายการกลับ ไม่ลบประวัติ
- ยอดแยก สินค้า + คลัง + ช่องเก็บ + สถานะคุณภาพ (ใช้ได้/รอตรวจ/กักกัน/รอแก้ไข) + ล็อต — ของรอตรวจ/กักกันเบิกไม่ได้

## โหมดข้อมูล (เลือกที่ปุ่มบนแถบด้านบน)

| โหมด | เก็บที่ | ใช้เมื่อ |
| --- | --- | --- |
| ข้อมูลตัวอย่าง | เบราว์เซอร์ของผู้เปิด (localStorage) | ทดลอง/อบรม สลับผู้ใช้ทดลองได้ เริ่มแบบมีข้อมูลตัวอย่าง (`DEMO-…`) หรือเริ่มว่าง |
| ข้อมูลทีม | ฐานข้อมูลร่วมของ Artifact (claude.ai) | ทีมเล็กทดลองร่วมกัน ผู้ใช้ผูกกับบัญชี claude.ai ผู้เปิดคนแรกเป็นผู้ดูแล |
| เซิร์ฟเวอร์ | Cloudflare Worker + D1 + R2 (`worker/`) | ใช้จริง 10–20 คน เซิร์ฟเวอร์เป็นผู้ตรวจและบันทึกคำสั่งเพียงรายเดียว |

ข้อจำกัดโหมดข้อมูลทีม: โปรแกรมในเบราว์เซอร์ของแต่ละคนเป็นผู้ตรวจคำสั่ง (เชื่อ client) และฐานข้อมูลของ Artifact
เก็บได้ราว 25,000 commit / 256 KB ต่อ commit เหมาะกับการทดลองกลุ่มเล็ก ใช้งานจริงให้ใช้โหมดเซิร์ฟเวอร์

### โหมดเซิร์ฟเวอร์ (แทน Google Sheet)

ตามที่ตกลงให้หลังบ้านบันทึกแบบ Sales Office/CRM: ข้อมูลหลักอยู่ใน **D1** ไม่ใช่ Google Sheet
- `sq_commits` เก็บทุก commit ต่อกันด้วย hash (ห้ามแก้/ลบด้วย trigger) `sq_records` เป็นสำเนาอ่านเร็วที่สร้างใหม่ได้เสมอ
- เขียนแบบ CAS: commit ใหม่ต้องต่อจาก seq/hash ล่าสุด ชนกัน = ตรวจใหม่บนข้อมูลล่าสุด requestId เดิมทำครั้งเดียว
- เข้าสู่ระบบแบบ Sales Office: cookie `__Host-sq_session` (HMAC) รหัสผ่าน bcrypt จำกัดจำนวนครั้ง ตรวจ Origin ทุก POST
- รูป/ใบรับรองเก็บใน **R2**
- **Google Drive** ใช้เป็นที่สำรอง (ปิดไว้ก่อน `SQ_DRIVE_BACKUP_ENABLED=false`) โฟลเดอร์ต้องเป็นส่วนตัว อ่านกลับมาตรวจ checksum ทุกไฟล์
  แท็บแบบ Google Sheet ยังส่งออกได้จากหน้า "พจนานุกรมข้อมูล" และ "สำรองและกู้คืน" เพื่อให้คนอ่าน — ไม่ใช่ข้อมูลหลัก
- **Sales Office**: รับใบงาน/SO ผ่าน Part List bridge ด้วยเลขที่ตรงตัว Domestic/Export แยกกัน (ปิดไว้ก่อน `SQ_SALES_BRIDGE=off`)
- ค่าเริ่มต้น staging: สวิตช์ทุกตัวปิด ไม่ส่งข้อความหรือคำขอออกภายนอกเอง

วิธีตั้งค่าและ deploy ทีละขั้น: `worker/README.md` (ยังต้องสร้าง D1/R2 จริง ตั้ง secret และได้รับอนุมัติก่อน)

## สิ่งที่ยังต้องตัดสินใจ

คำถาม ค-1 … ค-11 อยู่ในหน้า "ขอบเขต นโยบาย และข้อตกลง" — ค่าเริ่มต้นในระบบเป็นข้อเสนอเท่านั้น
(เช่น ยอดจำนวนเป็นของ RRS, ห้ามยอดติดลบ, แยกหน้าที่ผู้ทำ/ผู้อนุมัติ) จนกว่าผู้มีสิทธิ์จะบันทึกข้อสรุป เพิ่มเติม:
- ค-10 Sales Office รับตัวเชื่อมได้ **หนึ่งตัวต่อ workspace** — จะให้ระบบนี้หรือโปรแกรม ST01 เดสก์ท็อปเป็นตัวเชื่อม
- ใบงานที่เปิดอยู่เมื่อ BOM เปลี่ยนฉบับ: ตอนนี้ระบบแจ้ง `BOM_CHANGED` และต้องสร้างใบงานใหม่
- สินค้าสำเร็จที่รับเข้าด้วย FR ต้องจองให้ใบงานของตัวเองอัตโนมัติหรือไม่
- ของรอตรวจ (QC_HOLD) นับเป็นของที่ได้รับแล้วตอนแนะนำสั่งซื้อหรือไม่ (`qcHoldIsSupply`)
- ต้องสแกนก่อนจ่ายของหรือไม่, รูปแบบเลขที่ SO, ผู้มีสิทธิ์อนุมัติเมื่อมีปัญหาร้ายแรงระหว่างทดลอง

## ข้อจำกัดที่รู้แล้ว

- ยังไม่มี MFA — บัญชีเจ้าของต้องใช้รหัสผ่านยาวและเปิดเฉพาะเครือข่ายบริษัทได้ถ้าทำได้
- bcrypt ใช้ CPU มาก ต้องใช้ Workers แบบเสียเงิน (Paid) สำหรับเวลาที่ใช้ต่อคำขอ
- เซิร์ฟเวอร์เก็บข้อมูลทั้งหมดไว้ในหน่วยความจำของ isolate ระหว่างทำงาน (พอสำหรับ 10–20 คน ควรวัดอีกครั้งเมื่อข้อมูลโตมาก)
- นอกโหมดเซิร์ฟเวอร์ รูปและใบรับรองเก็บแค่ชื่อไฟล์/รูปย่อ ไม่ใช่ไฟล์จริง
- ยังไม่ได้ทดสอบกับ Cloudflare, Google หรือ Sales Office จริง — ใช้ของปลอมในเครื่องเท่านั้น
